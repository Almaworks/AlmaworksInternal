# CLAUDE.md — src/db/ (SHARP EDGE)

> This folder owns the database schema, types, and migrations.
> Read this before making any changes here.

## What lives here
- `types.ts` — auto-generated TypeScript types (DO NOT hand-edit)
- `seed.ts` — local development seed data
- `schema.sql` — reference schema (informational only)

## Non-negotiable rules
1. NEVER hand-edit `src/db/types.ts` — it is generated by `supabase gen types typescript --local > src/db/types.ts`
2. NEVER hand-edit files in `supabase/migrations/` — use `supabase db diff -f name` to generate
3. ALWAYS run type generation after any schema change — see .claude/skills/db-migration.md
4. EVERY program-scoped table must have `semester_id uuid not null references semesters(id)`. Global exemptions must be listed in `docs/architecture/identity-membership.md`.
5. EVERY new table must have RLS enabled — see docs/adr/002-rls-for-role-access.md

## Key tables (quick reference)
| Table | Sharp edge |
|---|---|
| `semesters` | Only one can have `is_active = true` at a time |
| `semester_memberships` | Role and cohort access source of truth; never trust auth metadata |
| `profiles` | Durable identity; nullable `auth_user_id` is the login link. Legacy role/semester columns are non-authoritative. |
| `meetings` | One Friday program date within a semester |
| `meeting_availability` | Unique per semester membership, meeting, and numeric slot (1 or 2) |
| `sessions` | One mentor-startup conversation in a meeting slot |
| `outreach_contacts` | Global outreach identity, intentionally independent from program profiles |
| `outreach_opportunities` | Per-semester outreach stage, ownership, and resettable workflow state |

Use the canonical vocabulary in database adapters: a semester is the cohort term, a meeting is one Friday date, and a session is one mentor-startup conversation in numeric slot 1 or 2. Do not introduce `sessionDate` or `timeSlot` aliases.

## After any schema change — run this
```bash
supabase gen types typescript --local > src/db/types.ts
```
Then commit `src/db/types.ts` in the same commit as the migration file.
