## Google connection and worker configuration

Connection setup additionally requires these server-only settings:

- `CALENDAR_APP_ORIGIN`: trusted app origin; local development accepts localhost HTTP.
- `GOOGLE_CALENDAR_CLIENT_ID` and `GOOGLE_CALENDAR_CLIENT_SECRET`: OAuth client with the exact callback `${CALENDAR_APP_ORIGIN}/api/calendar/callback` registered in Google Cloud.
- `GOOGLE_CALENDAR_ENCRYPTION_KEY`: canonical base64 encoding of a 32-byte key. Preserve it across releases so stored credentials remain decryptable.
- `CALENDAR_WORKER_EMAIL` and `CALENDAR_WORKER_PASSWORD`: ordinary dedicated Auth identity registered and enabled in the private Calendar worker table. Do not use a service-role key.
- `CALENDAR_CRON_SECRET`: at least 32 characters; authenticates the worker endpoint.

The standard allowlisted Supabase URL and public anon key are also required. Store secrets in the deployment environment, never source control, reports, or chat. Configure the recurring worker only after its database and authorization checks pass. A scheduler has not yet been installed.

If Google/worker configuration is missing after rollout, new connection setup is unavailable, but existing connection metadata, settings and the shared slot reader remain accessible under RLS. Synced slots with stale coverage remain unavailable according to the database predicate. The mentor can still switch to weekly mode or edit an existing manual import.
